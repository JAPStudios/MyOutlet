# MyOutlet

MyOutlet is an audiovisual publishing, streaming and creator platform. Its scope includes creator channels, on-demand and live media, live chat, viewer chat reports, creator timeouts and bans, search, moderation, content ratings, creator tools and audience song requests.

## Current repository structure

The Wix Velo site source is under `src/`. The browser extension files at the repository root are a separate legacy companion and are not the streaming service. The `upstream/` paths are pinned Git submodule entries; they are not imported application source.

## Backend catalogue and creator workflows

The backend service layer includes `src/backend/catalog.jsw` for creator discovery, published catalogue browsing and search with category, tag, rating, type and language filters, creator profiles with avatars, banners and social links, channel management, submissions, moderation and channel-scoped single or ordered multi-song requests. `src/backend/viewer.jsw` handles watchlists, playback progress, creator follows, followed-creator feeds, member-selected content-rating preferences and creator playback analytics. `src/backend/media.jsw` handles private MP4 uploads and published-video playback URLs. `src/backend/reports.jsw` handles member reports and owner-only moderation. `src/backend/engagement.jsw` handles media likes, comments, site-owner moderation and creator-channel comment moderation. `src/backend/playlists.jsw` handles creator-owned playlists and ordered media items. `src/backend/notifications.jsw` provides private notification inboxes for new follows, comments, song requests and followed creators starting live streams. `src/backend/rights.jsw` manages creator rights declarations, owner review, expiry checks and publication/playback gating. `src/backend/liveStreams.jsw` manages creator-owned RTMPS sessions and public live-stream discovery and playback lookup. `src/backend/liveChat.jsw` provides live-session chat reads, authenticated posting, rate limiting, creator/site-owner moderation, viewer reports and creator-channel bans and timeouts. `src/backend/http-functions.js` authorizes MediaMTX publishing and HLS reads. `src/backend/ratingPreferences.js` applies member-selected rating filters. `src/backend/events.js` records upload completion and video-transcoding readiness. The reusable front-end uploader in `src/public/mediaUpload.js` sends MP4 files to the signed upload URL and reports byte-level progress; the returned upload-session ID can then be passed to `submitContent` after the session reaches `ready`. See [CMS_COLLECTIONS.md](CMS_COLLECTIONS.md) for the required Wix CMS collection fields and access controls.

## Visitor-facing homepage

The existing Wix homepage has an enabled custom embed that loads `src/public/myoutlet-app.js` from this repository. The interface provides a media discovery catalogue, title/description/category search, video/audio and creator-rating filters, a live-broadcast section, public creator profiles and a media player. `src/pages/Home.c1dmp.js` connects the custom homepage to the Velo web modules for catalogue browsing, creator discovery, live-stream discovery and playback through a same-page request/response bridge. The live player also connects to the live-chat web module for message retrieval, signed-in posting and viewer reporting. The creator studio connects channel profile editing, MP4 uploads, media submissions, worldwide distribution-rights declarations, creator analytics, live-stream session creation and live song-queue moderation to the existing Velo web modules. The member library connects Wix member sign-in, creator follows and unfollows, watchlist saves, resume playback, continue-watching progress and persisted content-rating preferences. The media player connects likes, comments, content reporting and playlist additions to the backend. The member library includes playlist creation and management plus notification reading. A site-owner moderation area exposes pending rights declarations, media-review decisions, pending comment review, live-chat report resolution and content-report resolution; creator channels can also moderate comments on their own media; publication remains blocked until the backend confirms valid distribution rights. Uploaded videos remain private while Wix processes them and cannot be submitted until the upload session is ready. Live-stream creation requires the RTMPS and HLS service secrets described in [LIVE_STREAMING.md](LIVE_STREAMING.md), plus the required media-rights review before a stream can become public. Creator-supplied ratings are classifications and viewer filters; they are not identity or age verification.

The public HTTP functions return only published media with current worldwide rights records, active live sessions and public creator-profile fields. Wix-hosted uploaded videos use Wix-generated playback URLs; externally hosted media must use HTTPS. The application does not fabricate catalogue items when no published content is available.

## Functional boundaries

The current media workflow accepts private MP4 uploads into the Wix Media Manager, waits for Wix's video-transcoding event, and returns HLS or DASH playback URLs for published uploaded videos. Creator live sessions use RTMPS ingest through MediaMTX and authenticated HLS playback, with rights review and content moderation gating. Live chat is tied to an active, rights-cleared stream, is rate-limited to five messages per member per ten seconds, and supports creator-channel and site-owner moderation. Members can report chat messages; reports are private to the reporter and site owners, rate-limited, and reviewable through the owner-only moderation methods. Channel owners can also issue temporary timeouts or permanent chat bans and lift them. Because geographic access controls are not implemented, rights verification currently accepts worldwide distribution declarations only. The repository now includes a public playback path for published media and a basic scheduled Wix/CMS availability check. It does not yet provide public VOD archival/import, adaptive-bitrate transcoding, a custom CDN, verified age checks, payment processing or monitoring of the separate RTMPS/HLS streaming service. Content-rating preferences are viewer-selected filters, not age verification. Creator analytics report playback starts, bounded client-reported watch time and completions; they are not audited audience measurements. The chat-report workflow and creator ban/timeout methods are committed in the repository.

No payment is collected by the current backend. Song requests are queued as metadata only, scoped to one active live session, limited to 50 pending requests per stream and five per viewer; ending the stream cancels its remaining queue. They do not charge viewers and are not yet connected to NoiseGround song search or paid request checkout. No third-party media is licensed by the presence of a URL or catalogue record.

See [LIVE_STREAMING.md](LIVE_STREAMING.md) for the MediaMTX ingest/playback service and its Wix secrets.

## Availability monitoring

The public `/_functions/health` endpoint checks that the Wix backend can read the media and live-stream CMS collections. The scheduled GitHub Actions monitor checks this endpoint every five minutes and fails when the site or its CMS read path is unavailable. This is an uptime/readiness check for the Wix application; it does not certify the separate RTMPS/HLS streaming host, payment processing or media-delivery performance.

## Source validation

Run `node scripts/validate-backend.js` (or `npm test`) to check that all exported backend web methods have explicit permissions, private collections are documented, and the MyOutlet site binding, media event/uploader wiring and feature modules remain consistent. GitHub Actions syntax-checks every Velo JavaScript source file and validates every exported web method against the documented collections on relevant pushes and pull requests.
